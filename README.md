# مستقبلي الدراسي | MY STUDY FUTURE

منصة تعليمية عراقية عربية تربط الطالب بالمدرس، وتجمع المراحل الدراسية والدورات والدروس والاختبارات في تجربة واحدة متجاوبة مع الهاتف والكمبيوتر.

## الهوية والواجهة
- واجهة عربية RTL بهوية كحلية داكنة وبنفسجية مضيئة.
- صفحة تعريفية ومسارات للابتدائي والمتوسط والإعدادي والجامعة والدورات.
- دليل المدرسين يعرض الملفات التي اعتمدتها الإدارة فقط.
- واجهة الدورات والبحث ولوحات الحسابات تُحمّل من Supabase.
- صفحات الخصوصية والشروط متوافقة مع الهوية البصرية وتوضح أنها مسودات ما قبل الإطلاق.
- PWA قابلة للتثبيت، مع استراتيجية تحديث تمنع بقاء ملفات الواجهة القديمة في ذاكرة الهاتف.

## الوظائف الموجودة في الشيفرة وقاعدة البيانات
- Supabase Auth: إنشاء حساب طالب أو مدرس بالبريد، تسجيل الدخول والخروج، استعادة كلمة المرور وتعيين كلمة مرور جديدة.
- إنشاء ملف شخصي عند أول دخول.
- حساب المدرس يبدأ بحالة «بانتظار اعتماد الإدارة» ولا يظهر في دليل المدرسين العام قبل الموافقة.
- لوحة إدارة تعتمد على مطالبة موثوقة في `app_metadata.role=admin`، وليست على نوع الحساب الذي يختاره المستخدم.
- لوحة الإدارة: عرض حسابات الطلاب والمدرسين، مراجعة الدورات ونشرها أو أرشفتها، ومراجعة طلبات اعتماد المدرسين أو رفضها أو إعادتها للمراجعة.
- لوحة المدرس: تعديل الملف الشخصي، إنشاء الدورات كمسودات، إضافة الدروس، إعداد أسئلة متعددة الخيارات، مشاهدة أسماء الطلاب المرتبطين بدوراته عبر RPC محمي، متابعة الحجوزات، قبول التسجيل أو إكمال الدورة، وتأكيد الدروس أو إتمامها أو إلغاؤها.
- لوحة الطالب: تعديل الملف الشخصي، طلب التسجيل في دورة، طلب حجز درس، مشاهدة الدروس بعد قبول التسجيل، أداء اختبارات الدورات، متابعة النتائج، وتقييم الدورة بعد إكمالها.
- تصحيح الاختبارات يتم داخل دوال قاعدة البيانات، ولا تُرسل الإجابات الصحيحة إلى واجهة الطالب.
- دوال الاختبارات الحساسة موجودة في schema داخلي `private`، وتستدعيها واجهات RPC عامة بصلاحية invoker مع تحقق من هوية الطالب أو ملكية المدرس.
- جداول للملفات الشخصية والمواد والدورات والدروس والتسجيلات والحجوزات والتقييمات وأسئلة الاختبارات ومحاولاتها.
- سياسات RLS على الجداول، مع صلاحيات محدودة، وفصل صلاحيات الإدارة عن بيانات المستخدم القابلة للتعديل.
- لا يستطيع المدرس اعتماد نفسه حتى عند إنشاء الملف الشخصي؛ صلاحية إدخال حالة الاعتماد غير ممنوحة للمستخدم، والتحقق من الحالة يتم على الخادم.
- قيود قاعدة البيانات تتحقق من حالات التسجيل والحجز واعتماد المدرس وانتقالات الحالات، وتمنع تداخل حجوزات المدرس، ولا تعتمد على تحقق الواجهة وحده.
- يحتفظ الطالب المسجل بإمكانية الوصول إلى دورة اكتملت أو تغيّرت حالة مدرسها، مع بقاء الدورات الجديدة مرئية للعامة فقط عند اعتماد المدرس.
- التقييمات لا تُقبل إلا من طالب أكمل التسجيل في الدورة، ولا تُعرض بيانات التقييم الشخصية للعامة.
- ترويسات أمان أساسية على Netlify.

## حالة النشر
المصدر الحالي محفوظ على فرع `main`. آخر نسخة منشورة بنجاح على Netlify أقدم من بعض التعديلات الحالية. عمليات النشر اللاحقة تخطّاها Netlify بسبب تجاوز رصيد استخدام الحساب. لذلك لا تعتبر كل التعديلات الموجودة في GitHub ظاهرة على الموقع العام إلى أن ينجح نشر جديد.

## ما يزال مطلوباً قبل الإطلاق العام أو التجاري
1. **اختبارات المتصفح الفعلية** على الهاتف والكمبيوتر، والتحقق من تسجيل الطالب والمدرس واعتماد المدرس ونشر الدورة والتسجيل والحجز وإعداد الاختبار وتسليمه.
2. **ضبط إعدادات Auth في لوحة Supabase**: مراجعة Site URL وروابط إعادة التوجيه المسموح بها لتطابق نطاق الإنتاج. الكود يحدد رابط الإنتاج صراحةً، لكن إعداد لوحة Auth لم يتم التحقق منه بعد.
3. **البريد الإلكتروني**: إعداد SMTP موثوق وتجربة رسائل التأكيد والاستعادة من نسخة منشورة.
4. **الاختبارات**: تدفق إعداد الأسئلة والتصحيح الآمن موجود في الشيفرة وقاعدة البيانات، لكنه لم يختبر بمستخدمين فعليين على نسخة منشورة.
5. **المدفوعات**: لا توجد بوابة دفع حقيقية مفعّلة. لا تستخدم ZainCash أو أي مزود قبل الموافقة الرسمية والحصول على مفاتيح التكامل الرسمية وحفظ الأسرار في الخادم.
6. **التواصل والفيديو**: لا توجد محادثات داخلية أو فصول فيديو مباشرة مكتملة حالياً.
7. **حماية القاصرين**: استكمال موافقة ولي الأمر، وآليات الإبلاغ والحظر والإشراف، وعدم إتاحة تواصل غير مراقب مع القاصرين قبل اعتماد الضوابط المناسبة.
8. **إدارة المستخدمين**: استكمال أدوات إدارة الحسابات، البلاغات، الاعتراضات، وإجراءات الدعم.
9. **الوثائق القانونية**: سياسة الخصوصية وشروط الاستخدام مسودتان تشغيليتان، وتحتاجان مراجعة قانونية عراقية قبل الإطلاق.
10. **إعدادات أمان Auth**: أظهر Security Advisor أن حماية كلمات المرور المسربة غير مفعلة. يجب مراجعة إعداد Auth وتفعيلها إن كانت متاحة في الخطة.

## إعداد Netlify
- ملف `netlify.toml` يحدد مجلد النشر `.` ولا يحتاج إلى build command.
- اربط المستودع على الفرع `main` بالموقع الحالي.
- لا تضع أي أسرار في المستودع أو داخل `index.html` أو `app.js`.
- بعد عودة رصيد النشر، انشر آخر commit ثم اختبر النسخة المنشورة؛ لا تعتمد على حالة GitHub وحدها.
