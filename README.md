# مستقبلي الدراسي | MY STUDY FUTURE

منصة تعليمية عراقية عربية تربط الطالب بالمدرس، وتجمع المراحل الدراسية والدورات والملفات التعليمية في تجربة واحدة متجاوبة مع الهاتف والكمبيوتر.

## الهوية والواجهة
- واجهة عربية RTL بهوية كحلية داكنة وبنفسجية مضيئة.
- صفحة تعريفية، مسارات للابتدائي والمتوسط والإعدادي والجامعة والدورات.
- دليل المدرسين يعرض الملفات التي اعتمدتها الإدارة فقط.
- واجهة الدورات والبحث ولوحات الحسابات تُحمّل من Supabase.
- PWA قابلة للتثبيت، مع استراتيجية تحديث للشيفرات والصفحات حتى لا تبقى النسخة القديمة عالقة في ذاكرة الهاتف.

## الوظائف المنفذة في الشيفرة وقاعدة البيانات
- Supabase Auth: إنشاء حساب طالب أو مدرس بالبريد، تسجيل الدخول والخروج، استعادة كلمة المرور وتعيين كلمة مرور جديدة.
- إنشاء ملف شخصي عند أول دخول.
- حساب المدرس يبدأ بحالة «بانتظار اعتماد الإدارة» ولا يظهر في دليل المدرسين العام قبل الموافقة.
- لوحة إدارة تعتمد على مطالبة موثوقة في `app_metadata.role=admin`، وليست على نوع الحساب الذي يختاره المستخدم.
- لوحة الإدارة: مراجعة الدورات ونشرها أو أرشفتها، ومراجعة طلبات اعتماد المدرسين أو رفضها أو إعادتها للمراجعة.
- لوحة المدرس: إنشاء الدورات كمسودات، إضافة الدروس، متابعة طلبات التسجيل والحجوزات، قبول التسجيل أو رفضه، وتأكيد الحجوزات أو إلغاؤها.
- لوحة الطالب: طلب التسجيل في دورة، طلب حجز درس، مشاهدة الدروس بعد قبول التسجيل، ومتابعة الحجوزات ونتائج الاختبارات المتاحة.
- جداول للملفات الشخصية والمواد والدورات والدروس والتسجيلات والحجوزات والتقييمات وأسئلة الاختبارات ومحاولاتها.
- سياسات RLS على جداول البيانات العامة، مع فصل صلاحيات الإدارة عن بيانات المستخدم القابلة للتعديل.
- منع حساب المدرس من الظهور في الدليل قبل اعتماده.
- ترويسات أمان أساسية على Netlify وصفحتا الخصوصية والشروط.

## حالة النشر
المصدر الحالي محفوظ على فرع `main`. آخر نسخة منشورة بنجاح على Netlify أقدم من بعض التعديلات الحالية. عمليات النشر اللاحقة تخطّاها Netlify بسبب تجاوز رصيد استخدام الحساب. لذلك لا تعتبر كل التعديلات الموجودة في GitHub ظاهرة على الموقع العام إلى أن ينجح نشر جديد.

## ما يزال مطلوباً قبل الإطلاق العام أو التجاري
1. **إكمال اختبارات المتصفح الفعلية** على الهاتف والكمبيوتر، والتحقق من تسجيل الطالب والمدرس واعتماد المدرس ونشر الدورة والتسجيل والحجز.
2. **ضبط إعدادات Auth في لوحة Supabase**: مراجعة Site URL وروابط إعادة التوجيه المسموح بها لتطابق نطاق الإنتاج. الكود الحالي يحدد رابط الإنتاج صراحةً، لكن إعداد لوحة Auth لم يتم التحقق منه بعد.
3. **البريد الإلكتروني**: إعداد SMTP موثوق وتجربة رسائل التأكيد والاستعادة من نسخة منشورة.
4. **الاختبارات التعليمية**: الجداول موجودة، لكن واجهة إعداد الاختبار ومحاولة الطالب والتصحيح الآمن وعرض النتائج تحتاج إلى تنفيذ واختبار منفصل.
5. **المدفوعات**: لا توجد بوابة دفع حقيقية مفعّلة. لا تستخدم ZainCash أو أي مزود قبل الموافقة الرسمية والحصول على مفاتيح التكامل الرسمية وحفظ الأسرار في الخادم.
6. **التواصل والفيديو**: لا توجد محادثات داخلية أو فصول فيديو مباشرة مكتملة حالياً.
7. **حماية القاصرين**: استكمال موافقة ولي الأمر، وآليات الإبلاغ والحظر والإشراف، وعدم إتاحة تواصل غير مراقب مع القاصرين قبل اعتماد الضوابط المناسبة.
8. **الوثائق القانونية**: سياسة الخصوصية وشروط الاستخدام مسودتان تشغيليتان، وتحتاجان مراجعة قانونية عراقية قبل الإطلاق.
9. **مراجعة أمنية إضافية**: أظهر Security Advisor أن حماية كلمات المرور المسربة غير مفعلة؛ يجب مراجعة إعداد Auth وتفعيلها إن كانت متاحة في الخطة. ظهرت أيضاً مؤشرات معلوماتية عن فهارس غير مستخدمة، ولا تستدعي حذفها دون تحليل الاستخدام لاحقاً.

## إعداد Netlify
- ملف `netlify.toml` يحدد مجلد النشر `.` ولا يحتاج إلى build command.
- اربط المستودع على الفرع `main` بالموقع الحالي.
- لا تضع أي أسرار في المستودع أو داخل `index.html` أو `app.js`.
- بعد عودة رصيد النشر، انشر آخر commit ثم اختبر النسخة المنشورة؛ لا تعتمد على حالة GitHub وحدها.
